# Scout form, movement and platform practice

Status: local work in progress on `feat/scout-motion-polish`, based on deployed revision `1560d40a`. Nothing in this workstream is deployed yet. The [release record](RELEASE.md) describes the live combat-feedback release.

## Changes under development

The Blender scout's upper back and shoulders now form a more continuous human silhouette, with tapered ceramic plates following the upper arm. The original pack, palette, armor identity, skeleton, animation actions and weapon handling are retained. Neutral clay and unchanged-material Aim, Run, Fire, Reload and Heal comparisons are recorded in `art/source/scout-shoulder-pose-review.json`; the first open plate/sleeve intersection was corrected before the frozen export. A paired in-app-browser review loaded the exact old/new versioned GLBs in the actual GameView with the same high-quality lighting, position and shoulder camera. The fitted plates replace the old isolated round shoulder fittings; both scenes rendered without application errors. These controlled scenes were disposed and closed after inspection.

The frozen scout is 2,672,192 bytes, 21,658 vertices and 20,114 triangles, with SHA-256 `077be3e5789c136e1607e11cf7d9a243ee4324c44bc92877a3522d706e57bfd0`. Its versioned URL is `/models/scout.glb?v=scout-shoulders-v1`. Eighteen rest bones, inverse binds, both muzzle anchors and all 432 animation channels remain exact. Four body draws plus three AR draws are unchanged. Equipment geometry/skin data and embedded material images match; equipment UV rounding differs by at most 5.96e-8, so the complete equipment buffer is not byte-identical. The environment remains unchanged at SHA-256 `6a0cfc545e49d60519e8a71c933c9048a8aa4dfd7d38687a83b87cace9398d0d`.

Client movement prediction now applies reload/heal sprint restrictions already accepted by the server. The old path predicted 9 m/s while the server moved at 6.5 m/s, producing an 8.33 cm discrepancy per 30 Hz step. The helper tracks confirmed action deadlines through pending-input replay and subsequent frame prediction. Weapon switches cancel known restrictions before movement; deadline completion occurs afterward, following server order. New action starts still wait for authoritative snapshots. Future input arrival/coalescing remains approximate; this is not a duplicate combat simulator or a networking rewrite.

Character locomotion now follows resolved visible travel. A wall push can settle into idle, and sliding along a wall points the gait along the movement that actually occurred. A short filter absorbs interpolation noise. Local requested speed caps reconciliation motion; remote presentation follows its delayed visible position under the shared 9 m/s ceiling. Using newest remote velocity, or only the currently selected interpolation interval, could prematurely idle the final moving sample during a stop. Continued-snapshot regression and rendered checks now cover that boundary. Only the character's copied presentation velocity changes: authoritative snapshots, movement, camera position, collision, weapons and scoring remain intact. Each character's history resets on a new life, teleport, disconnect, visibility change or round reset.

Practice navigation now includes the existing south stairs and platform in an 83-node cached graph. The same physical step-up limit already permits players to walk this route. Bots follow supported routes and existing perception/reaction rules, with no new jumping, climbing, map geometry or movement privilege. A visible upper opponent can prompt ascent within normal firing distance. The follower preserves elevation during arrival, replanning, recovery and strafing; hidden movement cannot redirect the last-seen route.

## Acceptance

All 133 tests, TypeScript, both exported-asset checks and the production build pass. Eighteen focused client cases include actual-engine action restrictions, actual-physics wall stops/slides and continued-snapshot remote start/stop interpolation. Seven new practice cases cover all eight spawns and both stair directions at ordinary aim/walk/sprint speeds; supported shortcuts/recovery; visible versus hidden elevation; lifecycle; and full three-rival rounds at every difficulty. No shared map, physics, engine, protocol, loadout or scoring implementation changes are included.

Sixteen controlled actual-GameView/GLTF checks passed in installed Edge: confirmed AR/shotgun reload and heal prediction/FOV, sprint/aim, pending-input replay, real shared-physics wall stop/slide, remote delayed start/stop, teleport/visibility/round/respawn/disconnect resets, snapshot immutability and cleanup. The first rendered run exposed the final moving-to-static interval issue and prompted the remote-mode correction. Subsequent harness timing/cap expectations were corrected to match the documented interpolation delay, filter settling and remote ceiling. These fixtures use synthetic input/snapshots; real controls and transport require separate evidence. Fixed-budget rendering comparison, built-UI acceptance and deployment remain pending.

The exported gait's remaining foot slip and loop velocity seams are separate known limitations. Physical-phone rendering/controls and the [family playtest](FAMILY_PLAYTEST.md) remain open. This workstream makes no claim of Fortnite-level quality or verified phone performance.
