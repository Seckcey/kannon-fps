## Changes

The Blender scout's upper back and shoulders now form a more continuous human silhouette, with tapered ceramic plates following the upper arm. The original pack, palette, armor identity, skeleton, animation actions and weapon handling are retained. Neutral clay and unchanged-material Aim, Run, Fire, Reload and Heal comparisons are recorded in `art/source/scout-shoulder-pose-review.json`; the first open plate/sleeve intersection was corrected before the frozen export. A paired in-app-browser review loaded the exact old/new versioned GLBs in the actual GameView with the same high-quality lighting, position and shoulder camera. The fitted plates replace the old isolated round shoulder fittings; both scenes rendered without application errors. These controlled scenes were disposed and closed after inspection.

The frozen scout is 2,672,192 bytes, 21,658 vertices and 20,114 triangles, with SHA-256 `077be3e5789c136e1607e11cf7d9a243ee4324c44bc92877a3522d706e57bfd0`. Its versioned URL is `/models/scout.glb?v=scout-shoulders-v1`. Eighteen rest bones, inverse binds, both muzzle anchors and all 432 animation channels remain exact. Four body draws plus three AR draws are unchanged. Equipment geometry/skin data and embedded material images match; equipment UV rounding differs by at most 5.96e-8, so the complete equipment buffer is not byte-identical. The environment remains unchanged at SHA-256 `6a0cfc545e49d60519e8a71c933c9048a8aa4dfd7d38687a83b87cace9398d0d`.

Client movement prediction now applies reload/heal sprint restrictions already accepted by the server. The old path predicted 9 m/s while the server moved at 6.5 m/s, producing an 8.33 cm discrepancy per 30 Hz step. The helper tracks confirmed action deadlines through pending-input replay and subsequent frame prediction. Weapon switches cancel known restrictions before movement; deadline completion occurs afterward, following server order. New action starts still wait for authoritative snapshots. Future input arrival/coalescing remains approximate; this is not a duplicate combat simulator or a networking rewrite.

Character locomotion now follows resolved visible travel. A wall push can settle into idle, and sliding along a wall points the gait along the movement that actually occurred. A short filter absorbs interpolation noise. Local requested speed caps reconciliation motion; remote presentation follows its delayed visible position under the shared 9 m/s ceiling. Using newest remote velocity, or only the currently selected interpolation interval, could prematurely idle the final moving sample during a stop. Continued-snapshot regression and rendered checks now cover that boundary. Only the character's copied presentation velocity changes: authoritative snapshots, movement, camera position, collision, weapons and scoring remain intact. Each character's history resets on a new life, teleport, disconnect, visibility change or round reset.

Practice navigation now includes the existing south stairs and platform in an 83-node cached graph. The same physical step-up limit already permits players to walk this route. Bots follow supported routes and existing perception/reaction rules, with no new jumping, climbing, map geometry or movement privilege. A visible upper opponent can prompt ascent within normal firing distance. The follower preserves elevation during arrival, replanning, recovery and strafing; hidden movement cannot redirect the last-seen route.

## Acceptance

All 133 tests, TypeScript, both exported-asset checks and the production build pass. Eighteen focused client cases include actual-engine action restrictions, actual-physics wall stops/slides and continued-snapshot remote start/stop interpolation. Seven new practice cases cover all eight spawns and both stair directions at ordinary aim/walk/sprint speeds; supported shortcuts/recovery; visible versus hidden elevation; lifecycle; and full three-rival rounds at every difficulty. No shared map, physics, engine, protocol, loadout or scoring implementation changes are included.

Sixteen [controlled actual-GameView/GLTF checks](verification/scout-motion-renderer.json) passed in installed Edge: confirmed AR/shotgun reload and heal prediction/FOV, sprint/aim, pending-input replay, real shared-physics wall stop/slide, remote delayed start/stop, teleport/visibility/round/respawn/disconnect resets, snapshot immutability and cleanup. The first rendered run exposed the final moving-to-static interval issue and prompted the remote-mode correction. Subsequent harness timing/cap expectations were corrected to match the documented interpolation delay, filter settling and remote ceiling. These fixtures use synthetic input/snapshots; real controls and transport require separate evidence.

The [fixed-budget A/B/A comparison](verification/scout-motion-performance.json) used eight actually moving, animated characters on AMD integrated graphics at 1265×720, pixel ratio 1, Low quality, with five seconds of warmup and ten seconds of measurement per run. Median FPS was 53/54/53 for baseline/candidate/baseline. Draws stayed at 79; rendered triangles fell from 235,840 to 229,376. The first baseline had brief 30/14 FPS samples, retained in the report; candidate samples were 53–56 and the repeated baseline 49–54. These bounded samples support no observed regression, not a speedup or physical-phone claim. Every rig's actual ankles moved, and each browser received the matching frozen models. The [source receipt](verification/scout-motion-source.json) reconciles pre-commit working-tree checks to the subsequent implementation commit.

The [built desktop/touch flow](verification/scout-motion-ui.json) passed ten groups using real keyboard, mouse and emulated-touch input: private joining/countdown, both weapons, aiming, movement, reloads, jumping, mutual damage, timed heals, incomplete-round/rating handling, crews, portrait practice and difficulty re-entry/rotation. [Desktop](art/scout-motion-gameplay.png) and [touch](art/scout-motion-touch.png) captures show the actual built renderer. No application errors occurred. The initial flow recorded known sky precision warnings and 24 touch-driver `glGetProgramiv` warnings. A [fresh baseline comparison](verification/scout-motion-driver-review.json) reproduced 12 identical program warnings in unchanged `1560d40a` during first practice entry; the candidate produced only the known sky warning. Both builds rendered through re-entry and portrait/landscape rotation with matching models, successful program links, advancing snapshots, and no app errors or active context loss. Passive instrumentation found no invalid non-null program queries/use calls; it did not separately count null queries. The driver-internal cause remains unresolved. No warning suppression or product change was made, and this evidence does not establish physical-phone behavior.

[Isolated Linux acceptance](verification/scout-motion-linux.json) passed on Node 24.20.0 with one CPU, 512 MiB, no network interface/published port and temporary in-memory data. Seven frozen platform regressions exercised the built server/shared code; complete three-rival rounds had p95 engine steps below 0.23 ms. Eight real clients sent 14,394 inputs over 60 seconds, exercised ninth-player rejection and reconnect/fresh sequencing, and received about 15 snapshots/second; the worst recorded snapshot gap was 70.72 ms and latest acknowledged-input age 61.19 ms. Three practice difficulties each moved all three bots and produced valid shots while preserving rankings/history. Peak sampled usage was 16.44% CPU and 96.2 MiB. The owned candidate container/checkout were removed; production, all 65 protected containers and prior image tags were unchanged. This is loopback acceptance for one room, not wide-area latency or multi-room capacity.

The [deployment receipt](verification/scout-motion-deployment.json) verifies exact implementation `bbc40d344e62250dd88d75d7208c6570d66dcf57`, healthy status, zero restarts, origin/public HTTP and WebSocket smoke, matching models, and unchanged dedicated resource/security settings. An integrity-checked online SQLite backup preceded replacement. All seven existing profiles, one crew, one membership and empty results/rating tables were preserved; five older backups and fourteen prior image tags remained intact. [Public rendered practice](verification/scout-motion-live.json) then verified the exact build and `index-jzcelI6T.js` bundle over HTTPS/WSS, all three rivals moving and firing, one successful download per model with the pinned digest, and explicit exit without reconnecting.
